# Подготовка Google Sheets

Создайте отдельную таблицу для бота. Для демонстрации используйте вымышленные суммы.

## Доступ и настройки

1. В [Google Cloud Console](https://console.cloud.google.com/) создайте проект и включите Google Sheets API и Google Drive API.
2. Создайте сервисный аккаунт и JSON-ключ. Сохраните ключ локально как `credentials.json`; не загружайте его на GitHub.
3. В настройках доступа таблицы добавьте адрес сервисного аккаунта из поля `client_email` ключа с правом редактирования. Не включайте публичный доступ к таблице.
4. Скопируйте `.env.example` в `.env`. Укажите токен своего бота, ID своей таблицы и путь к ключу.

ID таблицы — часть её адреса между `/d/` и `/edit`:

```text
https://docs.google.com/spreadsheets/d/YOUR_SPREADSHEET_ID/edit
```

## Структура листов

Создайте пять листов. Заголовки — в первой строке. Сохраняйте порядок колонок: сервисы используют их позиции.

### `Users`

| A: username | B: user_id | C: digest_enabled | D: last_digest_date |
|---|---|---|---|
| your_telegram_username | | FALSE | |

Замените пример на свой username. При первом разрешённом обращении бот запишет Telegram user ID в B. Откройте чат и отправьте `/start`.

`FALSE` отключает сводку. Пустое значение или `TRUE` включает её; успешная отправка записывает дату в D для защиты от повторной отправки за тот же день.

### `Категории`

| A: категория | B: подкатегория | C: активно | D: порядок |
|---|---|---|---|
| Еда | Кафе | TRUE | 1 |
| Еда | Продукты | TRUE | 2 |

### `Лимиты_по_месяцам`

| A: категория | B: подкатегория | C: YYYY-MM |
|---|---|---|
| Еда | Кафе | 3000 |
| Еда | Продукты | 15000 |

Замените `YYYY-MM` на текущий месяц, например `2026-10`. Заголовок месяца должен быть текстом, а не датой. Для новых месяцев добавляйте колонки справа. Пары категория/подкатегория должны совпадать с листом `Категории`.

### `Траты_по_месяцам`

Создайте заголовки A–H в таком порядке:

| A | B | C | D | E | F | G | H |
|---|---|---|---|---|---|---|---|
| дата | месяц | пользователь | категория | подкатегория | сумма | комментарий | expense_id |

Оставьте остальные строки пустыми: бот добавляет записи сам. Колонка H содержит идентификатор для проверки действий изменения и удаления. Не меняйте её вручную.

### `Список покупок Продукты`

В A1 укажите `товары`, ниже — по одному товару на строку. Остальные колонки не используются.

## Проверка

Запустите бот по [README](README.md). При старте он проверит листы и обязательные заголовки. Внесите вымышленную трату в тестовом чате и проверьте результат в таблице.

При ошибке доступа проверьте включение API в проекте сервисного аккаунта, права редактирования таблицы, ID таблицы и путь к ключу в `.env`.

`test_google.py` добавляет произвольную тестовую строку в первый лист. Не запускайте его на рабочей таблице.

## Бизнес-бот и другие профили

1. В Telegram откройте официальный `@BotFather`, создайте отдельного бота командой `/newbot` и сохраните выданный токен для ввода в панели.
2. Создайте отдельную Google-таблицу. Можно скопировать структуру текущей таблицы, затем очистить расходы, пользователей, категории и даты сводок в копии. Исходную таблицу не изменяйте.
3. Подготовьте все пять листов по схеме выше. Названия листов, порядок и заголовки столбцов сохраняются. Пустой лист покупок пока тоже нужен: набор функций общий для всех профилей.
4. В `Категории` задайте бизнес-категории и подкатегории, например «Офис / Аренда», «Продвижение / Реклама». У активных строк укажите `TRUE`. В `Лимиты_по_месяцам` используйте такие же пары; если лимиты пока не заданы, сохраните хотя бы заголовки A/B.
5. В `Users` заполните **B: user_id** числовыми Telegram ID определённых участников. Username в A можно оставить пустым; для новых профилей он не предоставляет доступ. Каждый участник должен сам открыть чат с новым ботом и нажать «Старт», чтобы получать личные сообщения и сводки. `last_digest_date` оставьте пустым.
6. Предоставьте сервисному аккаунту Google право редактирования новой таблицы. Общий ключ допустим; бизнес-таблица и личная таблица остаются отдельными. Если нужен другой сервисный аккаунт, укажите путь к его ключу в форме профиля.
7. Откройте `bot.bat ui`, нажмите «Добавить бота». Введите название «Бизнес», ID `business`, ссылку на таблицу, валюту `RUB`, часовой пояс `Europe/Moscow` и токен. Нажмите «Проверить и сохранить».
8. Выберите «Бизнес», запустите его и отправьте `/start` от разрешённого пользователя. Первую реальную запись внесите самостоятельно и проверьте, что она появилась только в бизнес-таблице с нужными категорией и суммой. Личный бот продолжает работать независимо.

Числа в таблице храните как числа без символа валюты; в настройках форматирования Sheets можно выбрать рубли. Приложение выводит ₽ по настройке профиля, конвертации валют не выполняет. Все разрешённые участники видят общий бюджет своего бота. Это не выдаёт им автоматически права редактирования Google-таблицы: ими управляет владелец таблицы.

Проверка подключения не вносит финансовые записи. Ошибка схемы означает, что нужно исправить названия листов или заголовки и повторить проверку. Для третьего и последующих ботов повторите эти же шаги с новой таблицей и новым токеном.

## Источник денег (необязательно)

Эта возможность включается отдельно в профиле бота флажком «Учитывать источник денег». Для личного бюджета и старых профилей она выключена: их таблицы менять не требуется.

Перед включением для бизнеса создайте лист **`Источники`** с заголовками в указанном порядке:

| A: источник | B: активно | C: порядок |
|---|---|---|
| Счёт | TRUE | 1 |
| Наличные | TRUE | 2 |
| Карта | TRUE | 3 |

Названия произвольные. `TRUE` включает источник, `FALSE` исключает его из нового выбора. Должен оставаться хотя бы один активный источник. «Порядок» задаёт сортировку кнопок; одинаковые названия без учёта регистра и лишних пробелов показываются один раз.

В листе **`Траты_по_месяцам`** добавьте справа **I1: `источник`**. Заголовки A–H и H `expense_id` оставьте на своих местах. Старые строки в I оставьте пустыми: программа не определяет прошлые источники автоматически.

Затем остановите бизнес-профиль в панели, откройте его настройки, включите флажок и нажмите «Проверить и сохранить». Проверка потребует лист `Источники`, активные строки и правильный заголовок I. Запустите бизнес-бота и проверьте выбор источника при следующей трате.

Источник сохраняется текстом в I, сумма остаётся в F. Изменение суммы/комментария не стирает источник; через редактор сохранённой траты можно отдельно сменить источник. Удаление/переименование строки справочника не переписывает старые расходы. Для выключения функции остановите профиль и снимите флажок; лист и колонку можно сохранить для истории.
