# ТЗ: Структура работы Telegram-бота бюджета

## 1. Меню бота

### 1.1 Пункт меню: `Посмотреть лимиты`

#### Описание
При нажатии на кнопку `Посмотреть лимиты` бот показывает пользователю общий лимит на месяц и список категорий в виде кнопок.

#### Поведение
1. Пользователь нажимает кнопку `Посмотреть лимиты`.
2. Бот отправляет сообщение:
   - Текст: `Общий лимит на месяц: <сумма>`
3. Бот выводит inline-кнопки:
   - Одна кнопка = одна категория бюджета.
   - Название кнопки = название категории из таблицы `Бюджет`.

#### Источник данных
- Общий лимит на месяц: из листа `Бюджет` (ячейка с итогом, сейчас это значение `1817`).
- Категории: из листа `Бюджет`, столбец `Категория`.

### 1.2 Нажатие на кнопку категории

#### Описание
После нажатия на кнопку категории бот показывает детальную информацию по выбранной категории.

#### Формат сообщения
1. `🏷️ <b><название категории></b>`
2. `📊 Лимит / Потрачено / Осталось`
3. На следующей строке значения категории:
   - `<лимит категории €> / <потрачено в категории €> / <осталось в категории €>`
4. `🧾 Подкатегории:`
5. Для каждой подкатегории:
   - `• <название подкатегории>`
   - `Лимит / Потрачено / Осталось`
   - `<лимит подкатегории €> / <потрачено по подкатегории €> / <осталось в подкатегории €>`

#### Правила форматирования
1. Все денежные значения округляются до целого.
2. Разделитель тысяч — пробел.
3. После значения ставится знак `€`.
4. Строки со значениями выделяются жирным.
5. Если данных нет, показывается `—`.
6. Если `осталось < 0`, рядом с значением добавляется `⚠️`.
7. Под сообщением категории показывается inline-кнопка `💸Добавить трату`.

#### Поведение
1. Пользователь нажимает кнопку категории из блока `Посмотреть лимиты`.
2. Бот находит выбранную категорию в листе `Бюджет`.
3. Бот отправляет сообщение по формату выше.

### 1.3 Пункт меню: `Траты` (пошаговый диалог добавления траты)

#### Цель
Пользователь пошагово добавляет новую трату: категория -> подкатегория -> сумма -> подтверждение/комментарий.

#### Общие правила ветки диалога

1. На каждом шаге есть кнопка `Отмена`.
2. При нажатии `Отмена` ветка диалога завершается, бот пишет `Добавление траты отменено`.
3. Сообщение предыдущего шага удаляется после успешного перехода к следующему шагу.
4. Кнопки шага действуют только для текущего шага (контекстные кнопки, привязанные к текущему сообщению).

#### Шаги диалога

1. Пользователь нажимает кнопку `Траты` в основном меню.
2. Бот отправляет сообщение: `Введите категорию`
   - Показывает кнопки категорий из листа `Бюджет`.
   - Дополнительно кнопка `Отмена`.
3. Пользователь выбирает категорию.
4. Сообщение шага 2 удаляется.
5. Бот отправляет сообщение:
   - `Категория: <выбранная категория>`
   - `Выберите подкатегорию`
   - Кнопки: подкатегории выбранной категории.
   - Дополнительно кнопка `Отмена`.
6. Пользователь выбирает подкатегорию.
7. Сообщение шага 5 удаляется.
8. Бот отправляет сообщение:
   - `Категория: <категория>`
   - `Подкатегория: <подкатегория>`
   - `Введите сумму`
   - допускается формат: `<сумма> <комментарий>` (например: `12.50 кофе с собой`)
   - Дополнительно кнопка `Отмена`.
9. Пользователь вводит сумму текстом.
10. Сообщение шага 8 удаляется.
11. Бот отправляет сообщение подтверждения:
   - `Добавить трату: <категория>, <подкатегория>, <сумма>?`
   - `Можно добавить комментарий сообщением или Сохранить`
   - Кнопки: `Сохранить`, `Отмена`.
12. Пользователь завершает одним из способов:
   - Нажимает `Сохранить` -> трата записывается с текущими данными.
   - Вводит текст комментария -> считаем это подтверждением, комментарий сохраняется, трата записывается.
   - Нажимает `Отмена` -> запись не создается.

### 1.4 Пункт меню: `Посмотреть траты`

#### Описание
При нажатии на кнопку `Посмотреть траты` бот показывает последние 5 добавленных трат из листа `Траты`.

#### Поведение
1. Пользователь нажимает кнопку `Посмотреть траты`.
2. Бот читает валидные строки трат из листа `Траты` (по правилам раздела `3.2`).
3. Бот отправляет список последних 5 записей (новые сверху).
4. Если трат нет, бот отвечает: `Траты не найдены.`

#### Формат ответа
1. Заголовок: `Последние N трат:`
2. Для каждой записи:
   - дата,
   - сумма,
   - подкатегория,
   - пользователь,
   - категория (если указана),
   - комментарий (если есть).

## 2. Правило чтения данных из таблицы (фиксируем по колонкам)

Количество строк в таблице может меняться. Бот не должен зависеть от фиксированного номера последней строки.

### 2.1 Лист `Бюджет`

- Колонка `A`: `Категория`
- Колонка `B`: `подкатегория`
- Колонка `C`: `лимит подкатегории`
- Колонка `D`: `лимит категории`
- Колонка `E`: `потрачено по подкатегории`
- Колонка `F`: `потрачено в категории`
- Колонка `G`: `осталось в подкатегории`
- Колонка `H`: `осталось в категории`
- Колонка `I`: маркер `итого лимит месяц`
- Колонка `J`: значение `итого лимит месяц`
- Колонка `K`: маркер `итого потрачено месяц`
- Колонка `L`: значение `итого потрачено месяц`
- Колонка `M`: маркер `итого осталось месяц`
- Колонка `N`: значение `итого осталось месяц`

### 2.2 Как читать категории для кнопок

1. Читать колонку `A` начиная со 2-й строки.
2. Взять только непустые значения.
3. Убрать дубли, сохранить порядок появления.
4. Для каждой категории создать отдельную кнопку.

### 2.3 Как читать общий лимит месяца

1. Искать по колонке `I` строку, где текст равен `итого лимит месяц` (без учета регистра и лишних пробелов).
2. Брать значение общего лимита из колонки `J` той же строки.
3. Если такая строка не найдена, возвращать техническую ошибку: `Не найден общий лимит месяца в таблице`.

### 2.4 Как читать месячные итоги (новые поля)

1. `итого потрачено месяц`:
   - искать маркер в колонке `K`,
   - значение брать из колонки `L` той же строки.
2. `итого осталось месяц`:
   - искать маркер в колонке `M`,
   - значение брать из колонки `N` той же строки.
3. Если маркер не найден, возвращать техническую ошибку для соответствующего поля.

## 3. Лист `Траты`: структура и правила работы

### 3.1 Колонки листа `Траты`

- Колонка `A`: `дата` (формат в таблице: `dd.mm.yy`, пример `01.03.26`)
- Колонка `B`: `пользователь` (username Telegram, кто добавил запись)
- Колонка `C`: `категория` (может быть пустой, если используем только подкатегорию)
- Колонка `D`: `подкатегория`
- Колонка `E`: `сумма`
- Колонка `F`: `комментарий`
- Колонка `G`: служебный заголовок итога месяца (пример: `Траты март 2026`)
- Колонка `H`: значение итога трат за месяц (пример: `940,05`)

### 3.2 Как читать траты

1. Читать строки, начиная со 2-й.
2. Запись считается валидной тратой, если заполнены:
   - `A` (дата),
   - `B` (пользователь),
   - `D` (подкатегория),
   - `E` (сумма).
3. Поля `C` (категория) и `F` (комментарий) могут быть пустыми.
4. Чтение останавливать по фактическому концу данных листа (без фиксированного номера строки).

### 3.3 Куда вносить новую трату

1. Новая трата записывается в первую пустую строку после последней заполненной записи в колонках `A:F`.
2. Записывать значения по колонкам:
   - `A`: дата операции,
   - `B`: username пользователя Telegram (кто добавил запись),
   - `C`: категория (если есть),
   - `D`: подкатегория,
   - `E`: сумма,
   - `F`: комментарий (если есть, иначе пусто).
3. Колонки `G:H` бот не изменяет вручную (это зона формулы/ручного итога в таблице).
4. Запись выполняется в режиме `USER_ENTERED`, чтобы дата и сумма сохранялись как дата/число без префикса `'`.

### 3.4 Как читать итог трат за месяц

1. Искать в колонке `G` непустой маркер итога месяца (например, строка, начинающаяся с `Траты`).
2. Брать значение итога из колонки `H` той же строки.
3. Если маркер не найден, возвращать техническую ошибку: `Не найден итог трат за месяц`.

## 4. Валидация и устойчивость сценария `Траты`

### 4.1 Сумма

1. Бот принимает сумму в текстовом виде.
2. Допускаются вводы с `,` и `.` как разделителем дробной части.
3. Допускается объединенный ввод суммы и комментария в одном сообщении на шаге суммы:
   - формат: `<сумма><пробел><комментарий>`,
   - пример: `15,20 обед`,
   - первая числовая часть интерпретируется как сумма, оставшийся текст — как комментарий.
4. Перед записью бот автоматически:
   - нормализует значение к числу,
   - округляет до 2 знаков после запятой.
5. В таблицу сумма записывается в нормализованном виде с 2 знаками после запятой.
6. Невалидные значения (пусто, текст не число, отрицательное/нулевое) отклоняются с сообщением об ошибке.

### 4.2 Дата траты

1. Дата не запрашивается у пользователя.
2. При создании траты бот автоматически ставит сегодняшнюю дату (на момент записи).
3. Формат записи в колонку `A` листа `Траты`: `dd.mm.yy`.

### 4.3 Защита от повторной записи

1. Повторное нажатие `Сохранить` не должно создавать дубликаты одной и той же траты.
2. После успешной записи кнопки подтверждения считаются неактуальными.

### 4.4 Таймаут сценария

1. Если пользователь не отвечает в течение 15 минут, ветка добавления траты завершается.
2. При следующем сообщении пользователь начинает сценарий заново.

### 4.5 Удаление сообщений

1. Бот пытается удалять сообщение предыдущего шага.
2. Если удаление не удалось (ограничения Telegram/нет прав), сценарий продолжается без падения.

### 4.6 Устаревшие кнопки

1. Если пользователь нажал кнопку от старого шага, бот отвечает: `Шаг устарел, начните заново`.
2. Запись в таблицу по таким кнопкам не выполняется.

### 4.7 Неполные данные бюджета

1. Если у категории нет подкатегорий, бот сообщает об этом и не продолжает шаг выбора подкатегории.
2. Если у категории не заполнен лимит, бот показывает `не указан` (без падения сценария).

### 4.8 Ответ после успешной записи

1. После добавления траты бот отправляет итоговое сообщение:
   - что трата добавлена,
   - категория,
   - подкатегория,
   - сумма,
   - комментарий (если был).
2. Сразу после итогового сообщения бот автоматически открывает карточку той же категории:
   - `🏷️ <категория>`
   - лимит/потрачено/осталось по категории,
   - список подкатегорий с их показателями,
   - inline-кнопка `💸Добавить трату`.

### 4.9 Логирование

1. В лог пишутся:
   - `user_id`,
   - `username`,
   - категория,
   - подкатегория,
   - сумма,
   - статус операции (успех/ошибка),
   - текст ошибки (если была).

### 4.10 Повторная проверка доступа

1. Перед финальной записью траты бот повторно проверяет доступ пользователя по листу `users`.
2. Если доступ отозван, запись не выполняется.

## 5. Архитектура кода (реализовано)

1. `app.py`
   - запуск бота,
   - создание `Bot/Dispatcher`,
   - подключение роутеров.
2. `config.py`
   - чтение настроек (`BOT_TOKEN`, `SPREADSHEET_ID`, `GOOGLE_CREDENTIALS_FILE`).
3. `handlers/menu.py`
   - `/start`,
   - `Посмотреть лимиты`,
   - показ категорий и карточки категории,
   - fallback-ответ с главным меню.
4. `handlers/expenses.py`
   - весь диалог `Траты`,
   - обработчики callback и текстовых шагов,
   - отмена/подтверждение.
5. `handlers/shopping.py`
   - сценарий `Список Покупок`,
   - просмотр списка,
   - добавление/удаление/очистка,
   - обработка callback и текстовых шагов.
6. `services/google_sheets.py`
   - универсальные функции чтения/записи Google Sheets,
   - работа с листами `Бюджет`, `Траты`, `users`, `Список покупок Продукты`.
7. `services/access.py`
   - проверка доступа пользователей,
   - кэш разрешенных username.
8. `services/expenses.py`
   - бизнес-логика трат:
   - валидация суммы,
   - чтение последних трат,
   - формирование записи,
   - запись в таблицу.
9. `services/shopping.py`
   - чтение списка покупок,
   - добавление/удаление/очистка,
   - дедупликация и нормализация.
10. `state/expense_session.py`
   - модель `ExpenseSession`,
   - хранилище сессий, таймауты, защита от устаревших шагов.
11. `state/shopping_session.py`
   - модель `ShoppingSession`,
   - хранилище сессий сценария списка покупок.
12. `keyboards/main.py`
   - клавиатура главного меню.
13. `keyboards/limits.py`
    - inline-кнопки категорий лимитов.
14. `keyboards/expenses.py`
    - кнопки шагов ветки `Траты` (`категории`, `подкатегории`, `Сохранить`, `Отмена`).
15. `keyboards/shopping.py`
    - кнопки действий списка покупок (`Добавить`, `Убрать`, `Очистить список`, `Отмена`).

## 7. Главное меню: уточнение кнопок

1. Кнопки главного меню:
   - `📊 Посмотреть лимиты`
   - `🧾 Посмотреть траты`
   - `💸Добавить трату`
   - `🛒 Список Покупок`
2. Для кнопки расходов во всех местах используется единый текст: `💸Добавить трату`.
3. Раскладка кнопок в главном меню: по две кнопки в ряд (`2x2`).
4. Техническое ограничение Telegram:
   - в нижнем меню (`ReplyKeyboardMarkup`) жирный шрифт для текста кнопок не поддерживается.
   - HTML-теги в тексте таких кнопок не применяются.

## 6. Новый функционал: `Список покупок Продукты`

### 6.1 Кнопка в основном меню

1. В главное меню добавляется кнопка `Список Покупок`.
2. По нажатию бот открывает режим просмотра списка покупок из одноименной вкладки Google Sheets: `Список покупок Продукты`.

### 6.2 Отображение списка

1. Бот читает вкладку `Список покупок Продукты`.
2. Одна строка в сообщении бота = одна строка из таблицы (начиная со 2-й строки, если 1-я строка заголовок).
3. Если список пустой, бот пишет: `Список покупок пуст`.

Пример формата сообщения:
- `1. Молоко`
- `2. Хлеб`
- `3. Яйца`

### 6.3 Кнопки действий под сообщением списка

Под сообщением со списком бот показывает inline-кнопки:
1. `Добавить`
2. `Убрать`
3. `Очистить список`
4. `Отмена` (единая кнопка выхода из сценария, как в других ветках)

### 6.4 Действие `Добавить`

1. Бот запускает диалог добавления позиции в список.
2. Сообщение: `Введите позицию для списка покупок. Можно добавить несколько через запятую.`
3. Сообщение со списком покупок остается на экране в момент перехода к шагу добавления (не скрывается сразу после нажатия `Добавить`).
4. Пользователь отправляет текст:
   - одну позицию (`молоко`);
   - или несколько позиций через запятую (`молоко, хлеб, яйца`).
5. Каждая позиция обрабатывается отдельно:
   - обрезаются пробелы по краям;
   - пустые фрагменты между запятыми игнорируются.
6. Если позиция уже есть в списке, бот не создает дубликат, а помечает ее как уже существующую.
7. Максимальная длина каждой позиции: 120 символов.
8. Новые позиции записываются в первые пустые строки листа `Список покупок Продукты`.
9. После обработки бот показывает обновленный список и кнопки действий.

### 6.5 Действие `Убрать`

1. Бот показывает нумерованный список текущих позиций.
2. Бот отправляет сообщение: `Введите номер позиции для удаления`.
3. Пользователь может ввести:
   - один номер (`5`);
   - несколько номеров через запятую (`5,7,9`).
4. Бот удаляет выбранные строки из листа `Список покупок Продукты` в рамках одного шага.
5. После удаления бот показывает обновленный список и кнопки действий.

### 6.6 Действие `Очистить список`

1. Бот запрашивает подтверждение: `Очистить весь список покупок?`
2. Кнопки: `Да`, `Отмена`.
3. При `Да` бот очищает все строки списка (включая строку заголовка, если она есть).
4. Бот отправляет сообщение: `Список покупок очищен` и показывает пустой список с кнопками действий.

### 6.7 Правила данных для листа `Список покупок Продукты`

1. Основной рабочий столбец: `A`.
2. Пустые строки внутри списка игнорируются при отображении.
3. При добавлении пробелы по краям обрезаются.
4. Пустой ввод не сохраняется.
5. Порядок отображения списка = порядок добавления в таблицу.
6. Обработка действий выполняется в порядке поступления событий.

### 6.8 Защита и устойчивость

1. На каждом шаге ветки доступна кнопка `Отмена`.
2. При `Отмена` сценарий завершается без дополнительного служебного сообщения.
3. Для действий по старым/неактуальным кнопкам бот отвечает: `Шаг устарел, начните заново`.
4. Ошибки чтения/записи в Google Sheets возвращают пользователю сообщение: `Не удалось обновить список покупок. Попробуйте позже.`
5. Права на просмотр и редактирование списка есть у всех пользователей, прошедших базовую проверку доступа по листу `users`.
6. Все операции логируются: `add`, `remove`, `clear` с `user_id`, `username`, значением позиции/номера и статусом (успех/ошибка).
7. Сравнение дублей выполняется с нормализацией: без учета регистра и лишних пробелов (`"Молоко"` = `" молоко "`).
8. При некорректном номере для удаления бот отвечает: `Неверный номер, попробуйте снова`.
9. Если список пуст и пользователь выбрал `Убрать`, бот отвечает: `Список пуст, удалять нечего`.

## 7. Изменения от 2026-03-10

### 7.1 Удаленный перезапуск бота из Telegram

1. Добавлена текстовая команда `перезапуск` (без кнопки).
2. Команда доступна только пользователям, прошедшим проверку доступа по листу `Users`.
3. После команды бот отправляет подтверждение пользователю и планирует перезапуск через 5 секунд.
4. Перезапуск выполняется через `os.execv(sys.executable, [sys.executable, *sys.argv])`.
5. Добавлена защита от повторного запуска перезапуска: пока перезапуск уже запланирован, повторная команда не запускает второй цикл.

### 7.2 Рассылка при старте

1. При запуске бот выполняет стартовую рассылку сообщения `Бот запущен`.
2. Получатели берутся из листа `Users`, колонка `B` (`user_id/chat_id`).
3. Пустые, заголовочные и невалидные значения пропускаются.
4. Ошибки отправки отдельным пользователям не останавливают запуск бота и логируются.
5. Если список получателей пуст, бот логирует, что рассылка пропущена.

### 7.3 Автозаполнение user_id/chat_id в листе Users

1. Добавлена автоматическая синхронизация `user_id` пользователя с листом `Users`.
2. Синхронизация выполняется после успешной проверки доступа (в message и callback обработчиках).
3. Связка ищется по `username` из колонки `A` и записывается в колонку `B` той же строки.
4. Если в колонке `B` уже актуальный `user_id`, повторная запись не выполняется.
5. Если `username` не найден в `Users`, запись не создается автоматически (доступ по-прежнему определяется списком в колонке `A`).

### 7.4 Технические примечания

1. Для стартовой рассылки у пользователя должен быть открыт диалог с ботом (бот не может написать первым без инициированного чата).
2. Команда `перезапуск` работает для процесса бота, запущенного напрямую; при использовании внешнего менеджера процессов возможно альтернативное поведение перезапуска, зависящее от менеджера.

### 7.5 Обновление ветки `Список покупок` (добавление)

1. При нажатии `Добавить` бот больше не удаляет сообщение с текущим списком покупок до ввода пользователем текста.
2. Добавлен пакетный ввод позиций через запятую в одном сообщении пользователя.
3. По результату ввода бот отправляет отдельные статусы:
   - `Добавлено (N): ...` для новых позиций;
   - `Уже в списке (N): ...` для дублей.

### 7.6 Обновление ветки `Траты` (после успешного добавления)

1. После успешной записи траты бот сохраняет текущее итоговое сообщение (`Трата добавлена...`).
2. Затем бот автоматически отправляет карточку выбранной категории в формате раздела `1.2`.

### 7.7 Обновление ветки `Траты` (ввод суммы)

1. На шаге суммы поддержан формат `сумма + комментарий` в одном сообщении пользователя.
2. При подтверждении кнопкой `Сохранить` используется комментарий, введенный на шаге суммы (если он был).
3. Пользователь по-прежнему может ввести другой комментарий на шаге подтверждения, чтобы переопределить ранее введенный.

### 7.8 Обновление ветки `Список покупок` (удаление)

1. На шаге `Убрать` поддержан ввод нескольких номеров через запятую (`10,11,12`).
2. Бот удаляет все корректные выбранные позиции в рамках одного сообщения.
3. После удаления бот отправляет агрегированный результат вида `Удалено (N): ...`.

### 7.9 Обновление главного меню и просмотра трат

1. В главное меню добавлена кнопка `🧾 Посмотреть траты`.
2. По нажатию бот показывает последние 5 трат из листа `Траты` (новые сверху).
3. Главное меню перестроено в раскладку `2x2` (по две кнопки в ряд).
