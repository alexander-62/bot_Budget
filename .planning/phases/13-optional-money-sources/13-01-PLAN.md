# Optional source of funds — executable plan

## Task 1: Profile, Sheet contract and persistence

Append strict boolean `track_money_source=False` to BotProfile and expose runtime setting. Load own-sheet active sources with deterministic ordering and deduplication through the existing adapter. Extend SavedExpense with default blank source and safe write/update/read support for I; preserve legacy default tuple API and A:H writes when disabled. Schema validation requires extra sheet/column only when enabled and catches wrong positions before writes.

Verification: `.venv/Scripts/python.exe -m unittest discover -s tests -p test_money_sources.py -v` (or actual named new data tests), plus existing expense/profile/schema tests. Cover false default, malformed flag, enabled validation, active/inactive/empty sources, label/formula safety, append identity, historical blanks, amount-only update preservation and stale external source edits.

Recovery: validation errors stop startup/save with actionable messages; no automatic Sheet migration. Failed source reads never fall back to personal data or an invented source.

## Task 2: Telegram flow and saved edits

Add source selection between subcategory and amount only when enabled, snapshot source list for indexed callbacks, revalidate on new save and check session/action identity after awaits. Repeat asks source again. Add «Изменить источник» only in enabled saved-expense editor; preserve amount/comment and use existing stable expense identity checks. Confirmation and recent expenses display escaped source, including «Не указан» for old rows.

Verification: `.venv/Scripts/python.exe -m unittest discover -s tests -p test_money_source_flow.py -v`, then existing saved-action and concurrency modules. Cover disabled no-read path, enabled save/edit/repeat, cancel, stale/foreign/malformed callbacks, changed source order and inactive source rejection. Source changes must not mutate another expense or drop unrelated fields.

Recovery: empty source list explains how to add active rows. A stale record invalidates the saved action and never performs a write. Cancelled source editing leaves the expense intact.

## Task 3: Desktop toggle, documentation and integrated verification

Add profile checkbox in scrollable labeled form, persist explicit boolean after connection validation, default false for create and old profiles. Keep legacy personal off by default. Document optional sheet/column and business enablement sequence, bump runtime version to 1.6.1. Run all isolated modules, publication check and diff checks; record results in SUMMARY/VERIFICATION and STATE.

Verification: desktop form tests with mocked validation/save for flag true/false and real widget reflection; `.venv/Scripts/python.exe scripts/run_tests.py`; `.venv/Scripts/python.exe scripts/check_publication.py`; `git diff --check`. No live polling, token inspection or financial writes. Changes stay local until an explicit GitHub push request.
