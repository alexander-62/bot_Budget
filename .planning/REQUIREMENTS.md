# Requirements: v1.8.0 Будущие траты

**Defined:** 2026-11-20

## v1 Requirements

### Phase 18

- [x] **FUT-01**: Оператор включает будущие траты отдельно для каждого профиля; старые профили по умолчанию выключены.
- [x] **FUT-02**: При выключенном флаге меню, обработчики и напоминания отключены, лист не требуется; сохранённые планы не удаляются.
- [x] **FUT-03**: Пользователь создаёт план с названием, категорией/подкатегорией, необязательными суммой/датой и комментарием.
- [x] **FUT-04**: Участники бюджета видят общий список: просроченные, ближайшие, без даты; могут изменить/отменить план и открыть историю.
- [x] **FUT-05**: Планы сохраняют постоянный ID и автора; открытые планы не меняют фактические расходы/лимиты; данные изолированы по профилям.

### Phase 19

- [x] **PAY-01**: Пользователь подтверждает фактические сумму/дату и источник при включённом учёте источников; расход записывается за дату оплаты.
- [x] **PAY-02**: Оплата атомарно создаёт фактическую трату и закрывает план со ссылкой на expense_id, сохраняя историю и подтвердившего пользователя.
- [x] **PAY-03**: Двойное нажатие, два пользователя и потеря ответа после записи не создают повторного расхода; повторная попытка читает сохранённый результат.
- [x] **PAY-04**: Неавторизованные, устаревшие и чужие сессионные кнопки отклоняются; оплата проверяет актуальность плана и справочников.

### Phase 20

- [x] **REM-01**: В 21:30 в часовом поясе профиля создатель получает напоминание за день/в день оплаты и ежедневно при просрочке.
- [x] **REM-02**: Для планов без даты создатель получает общий список по понедельникам; оплаченные/отменённые планы исключены.
- [x] **REM-03**: Подписка на будущие платежи независима от digest_enabled; отметки доставки переживают перезапуск; неудачи повторяются без блокирования обычной сводки.
- [x] **REM-04**: Кнопка из напоминания открывает актуальную карточку и позволяет оплатить/изменить план; отключённый флаг блокирует старые кнопки.

## Future Requirements

Повторяющиеся платежи, частичные оплаты, несколько ответственных, индивидуальное расписание.

## Out of Scope

Автоматическое проведение расходов без подтверждения, изменение сумм по курсу, доступ к живым финансовым данным при проверках. Для первой версии — один процесс бота на бюджет, как в текущей архитектуре; параллельное ручное редактирование строк во время подтверждения не является транзакционно защищённым сценарием Sheets.
