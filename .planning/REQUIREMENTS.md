# Requirements: v1.6.0 Multiple Budget Bots

**Defined:** 2026-10-21
**Core value:** Быстро и надёжно записывать расходы в независимые бюджеты из одной панели.

## v1 Requirements

### Profiles
- [ ] **PROF-01**: Произвольное число профилей без изменения кода: ID, имя, таблица, валюта, часовой пояс, автозапуск.
- [ ] **PROF-02**: Существующий личный бот работает с прежними настройками и данными без ручной миграции.
- [ ] **PROF-03**: Токены отдельно от JSON, Git и журналов; некорректные ID, повторный Telegram-бот или таблица отклоняются.

### Data and access
- [ ] **DATA-01**: У каждого бота собственная таблица, категории и Users; разрешённые пользователи видят общий бюджет только своего бота.
- [ ] **DATA-02**: RUB в бизнес-расходах, итогах и сводках; EUR у personal. Дата и сводки учитывают часовой пояс профиля.
- [ ] **AUTH-03**: Новые профили проверяют числовой Telegram user ID; legacy-доступ личного бота сохраняется.

### Process management
- [ ] **PROC-01**: Независимые запуск/остановка/перезапуск, память, PID, блокировки, журналы.
- [ ] **PROC-02**: Health сверяется с профилем и PID; чужой процесс на старом порту не показывает ложную готовность.
- [ ] **PROC-03**: Одна панель и трей; Windows-автозапуск запускает только отмеченные профили.

### Desktop panel
- [ ] **UI-01**: Выбор бота, состояние, управление, открытие его таблицы и журнала.
- [ ] **UI-02**: Добавление/редактирование с маскированным токеном; третий бот подключается без изменения исходников.
- [ ] **UI-03**: Telegram-токен и схема Sheets проверяются до сохранения; безопасные ошибки и отзывчивый UI.
- [ ] **UI-04**: Запоздалый ответ не применяется к другому профилю; работающий профиль нельзя незаметно перенастроить.

### Verification and onboarding
- [ ] **TEST-05**: Fakes подтверждают изоляцию двух профилей и добавление третьего; старые tests проходят без секретов/живых записей.
- [ ] **DOC-01**: Руководство: Telegram-бот, схема бизнес-таблицы, Users IDs, доступ сервисного аккаунта, RUB-профиль в панели.

## Future Requirements

Серверное размещение, удалённая панель, общий ограничитель Sheets-нагрузки, база данных при измеренной необходимости, явная миграция личного доступа на ID, профильный выбор shopping/limits.

## Out of Scope

SaaS/биллинг, гарантия бесконечной одновременной нагрузки, расширение прав изменения чужих расходов, автоматические живые финансовые записи при тестировании.
